# Explicit radio mix actions (LB-19)

All routes require the existing authenticated session and return `Cache-Control: no-store` on success. LB-17/18 GET routes remain read-only.

- `POST /api/radio-mixes/preview`: JSON `kind` (`artist` or `discovery`), exactly one `artist_mbid` (UUID) or `tag`, `familiarity` (`familiar`, `explore`, `deep_cuts`) and `mode` (`easy`, `medium`, `hard`). Artist Radio requires an artist MBID; count is 40. Validation and provider budgets reuse LB-17/18.
- A ready result adds `preview_id` (32 lowercase hex characters), `kind`, `title`, `seed`, `total_count` and `owned_count` to the original preview. Every row has a zero-based `position`, `match_state`, `song_id`, and `duration_ms`. Artist rows also retain LB-17 fields. Empty, unconfigured and provider-failure responses do not create previews.
- The immutable, server-generated source list is stored in `intelligence.sqlite3`, scoped to the Navidrome server/account. Only the latest 50 unused previews per target are retained; save intents and completed saves are retained for idempotence. Previews are separate from the Playlist Inbox and scheduled reconciliation.
- `GET /api/radio-mixes/{preview_id}` reads that exact source list with current index ownership and discovery acquisition status. It never regenerates the mix. Unknown ownership remains null; imported tracks require indexing before becoming owned. Discovery rows reuse the Inbox acquisition fields.
- `POST /api/radio-mixes/{preview_id}/tracks/{position}/download` resolves the stored discovery occurrence. It reuses LB-09's complete live ownership check, album resolution, identity refusal and acquisition deduplication. Artist Radio downloads and invalid positions return `404`. Client-supplied track metadata is ignored.
- `POST /api/radio-mixes/{preview_id}/save` saves only confirmed owned tracks, preserving source order and repeats. Artist Radio revalidates exact song IDs and recording metadata; Discovery Mix rematches the source recordings against a complete live inventory. Scans or connection changes refuse the operation. Zero owned tracks return `409` without creating a playlist.
- Before remote creation, persist the selected IDs and unique creation marker. Verify owner, marker and privacy before adding tracks. Retry uses the same playlist and frozen selection; an unknown creation outcome remains pending without another create. Failed privacy verification never populates the copy. Missing or altered pending copies are refused.
- Success: `{state: "saved", playlist_id, saved_count}`. Repeated saves return the recorded success without modifying the playlist, including later owner edits or deletion. Saves are private, independent snapshots; they never auto-update after downloads or scans. Generate a new preview to save another playlist.
- Missing/cross-target previews return `404`; invalid parameters `422`; busy, zero-owned, identity or uncertain-save conflicts `409`; unavailable stores/providers `503`. Error `detail` is a safe display string. Acquisition refusals preserve their LB-09 HTTP status.

Web opens a shared preview dialog from artist pages and Discover music. Owned artist pages expose Artist Radio and Discovery Mix; unowned artists expose Discovery Mix when an MBID exists. Discover searches library artists by name or accepts a discovery tag. No browser playback or queue is added.

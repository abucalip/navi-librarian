# Listening Room: web client redesign

Status: **L0–L2 merged. L3 in review.** The owner picked direction A ("Listening Room") on 2026-11-17 from three Home mockups, and asked that it explain each pick's reasons more fully, in the way direction C did. The owner then asked for mockups of **every** web page, with **no Paths** (Paths is exclusive to Android and macOS), and for the reasons behind each pick to be **showcased: given a prominent place of their own**, not literally centre-aligned. This document is the design system and the build plan. The package it refers to is [`docs/design/listening-room/`](../design/listening-room/).

Scope: the browser client (`static/`, `app/templates/index.html`, `app/templates/login.html`). The Android and macOS clients are not touched. Every web page is designed here: Home (section 7) and every other page (section 8), each with a 1440 and a 390 mockup. The owner's rule is that mockups are the spec.

## 0. Read this first

1. **Where the spec lives.** Values live in [`tokens.json`](../design/listening-room/tokens.json). Measurements live in [`components.css`](../design/listening-room/components.css). If this text and those files disagree, the files are right. [`tokens.css`](../design/listening-room/tokens.css) and the icons are generated by `_src/build.py`; do not edit them by hand.
2. **Every reason is built from fields the server sends** (section 6). The direction-C mockup had sentences such as "Pharoah Sanders is all over your last month". The server cannot back sentences like that, so they are not part of this design. When no field applies, a card shows no reason line.
3. **Reasons are the showcase.** Every pick's reason sits in its own reason panel (5.6): a filled block with a 3px rule, a "Why this pick" label carrying the kind's icon, the sentence in Instrument Sans at full text strength, then the evidence chips. It is left-aligned like everything else; the prominence comes from the panel, the size and the contrast.
4. **No Paths on the web.** The web client has no Paths page, menu item, Home section or icon.
5. **Decisions for the owner** are in section 10. Each has a recommendation. Until the owner answers, the build plan assumes the recommended option.
6. **No player.** The web client does not play music. The main action on an album is **Get**; More like this, Skip and the "…" menu are secondary. Radio plays in the apps, and the web shows only "Grab the radio" and Heard.
7. **Server-side rule.** Domain logic stays on the server. The browser only puts the server's fields into words (section 6) and lays them out. If D1 is answered "server", the server writes the words too.

## 1. The idea

A dark, quiet room built around one album. Home opens on a single **lead pick**: a large cover, the reason in one full sentence, the evidence for it as chips, and one amber **Get** button. The lead pick's panel takes its colour from the cover. Below it, each discovery feature has its own calm section, and every album in those sections carries a short line saying why it is there.

### 4.3 The lead pick's colour

The panel behind the lead pick takes its colour from the cover. The cover colour comes from the browser: the page draws the cover once into a 16×16 canvas. The server does not send a colour.

```js
// Reference: must give the same colour as hero_tint() in _src/check_contrast.py.
function heroTint(img) {                         // img: the loaded lead cover <img>
  try {
    const c = document.createElement('canvas'); c.width = c.height = 16;
    const g = c.getContext('2d', { willReadFrequently: true });
    g.drawImage(img, 0, 0, 16, 16);
    const d = g.getImageData(0, 0, 16, 16).data;  // throws SecurityError on a cross-origin cover without CORS
    let r = 0, gg = 0, b = 0, w = 0;
    for (let i = 0; i < d.length; i += 4) {      // weight saturated pixels, so a white border does not win
      const mx = Math.max(d[i], d[i+1], d[i+2]), mn = Math.min(d[i], d[i+1], d[i+2]);
      const wt = 1 + (mx - mn) / 32; r += d[i] * wt; gg += d[i+1] * wt; b += d[i+2] * wt; w += wt;
    }
    return clampTint([r / w / 255, gg / w / 255, b / w / 255]);
  } catch { return null; }                       // null: use --lr-hero-fallback
}
// clampTint: to HLS, keep the hue, saturation = min(s, 0.5), lightness from 0.20 down in steps
// of 0.01 until relative luminance <= 0.04 (never below 0.06). Then set --lr-hero-tint.
```

- **The cover you see is never put at risk by sampling.** With `crossOrigin` set, an `<img>` whose host sends no CORS header fails to load at all. So the visible cover is a normal `<img>` without `crossOrigin`, and sampling uses a second, hidden image.
- **Owned covers** (`/api/owned/artwork/<id>`) are same-origin, so they are sampled straight from the visible `<img>` after it loads.
- **Covers for albums you don't own** come from the URL that `/api/artwork` returns, which is usually a provider's image host. They are sampled from a second `const probe = new Image(); probe.crossOrigin = 'anonymous'; probe.src = url;`, which is never put into the page. If `probe` fails to load, or `getImageData` throws, the panel keeps the fallback `#2A1F33`. The visible cover is unaffected either way.
- **How often it fails.** Most lead picks are not owned, so slice L3 records how often the fallback is used. If it is used often, D4 applies.
- **Contrast stays safe whatever the colour.** The clamp caps the panel's luminance at 0.04, so white text, the soft text `#E4E1E8` and the neutral buttons' labels pass 4.5:1 on every possible tint, and their edges (`rgba(255,255,255,0.44)`) and the accent pass 3:1. `check_contrast.py` checks 1,301 colours, both ends included; the lowest text ratio is 8.57.
- **No text sits over the art.** Text never lies on the cover, so no scrim is needed.

## 6. Why this pick: the reason block

### 6.1 Precedence

For each album, the first kind that applies wins:

1. R1 `bridge_label`
2. R2 `because.kind = tag`
3. R3 `because.kind = similar_artists`
4. R4 `similar_to` (adjacent recommendations, older server)
5. R5 lens with a seed tag
6. R6 lens without a seed tag
7. The list's own kind: R7/R8 Deep Dives, R9 New releases, R10 Collection, R11 Discover music
8. R12 owned
9. nothing

This is the order today's `reasonLine` in `static/app.js` uses, extended. It is also the order Android's `GalleryListsRules.tileReason` uses, so the clients agree.

### 6.4 Rules

- **Honest wording.**
  - Tag overlap (R3, R4) never says "because you play" or "you love {artist}".
  - Never put a count, a time period or a listening claim into a sentence unless a field carries it.
- **Numbers.**
  - Listener counts are shown short ("41k listeners", "9.6k listeners", "1.2M listeners"), and the full number goes in the chip's `title` and `aria-label`.
  - Library counts use "1 album" / "{n} albums".
- **Names and tags.**
  - Names are listed with ", " and "and" before the last; past 2 names, add "and {n} more".
  - Tags appear in the case the server sends.
- **Chips.** Seed tags and tags link to `/api/genres/<tag>`'s page, and artists link to the artist page. An artist photo comes from the existing `/api/artist-image` loader, which is cached. If no photo loads, the chip shows the artist's initials on `raised`.
- **Screen readers.** The evidence list is `<ul aria-label="Why this pick">`. The sentence is read first.

## 8. Every other page

Each page below has `pages/<name>.html` (open it to measure), `<name>.png` (1440) and `<name>-phone.png` (390). ### 8.1 Discover (`discover`, `discover-daily`, `discover-personal`, `discover-dives`, `discover-collection`, `discover-new`)

- **One page for the six lists.** Today's six separate pages (Discover music, Daily picks, Personal Discoveries, Artist Deep Dives, Add to your collection, New releases) become one Discover page with a **list switch** (`lr-listswitch`, `role="tablist"`). The menu item "Discover" opens the last list used (stored per browser); Home's "See all" and "Open Discover" open the matching list.
- **Each list** has its title, the one-line description from today's page, its own controls and a status line (`role="status"`), then a **ranked list** (`lr-rank`): rank number, cover 96, title and artist · year, the **reason panel at card size beside the title**, then Get, Save and "…".
- **Discover music:** the Albums count (5/10/15/20) and **Generate recommendations** (the one primary button in this view), then the Refine toolbar (search, category filter, sort), the count line, the rows (R4, R11) and the collapsed diagnostics.
- **Daily picks:** the lens tabs (5.7), "{n} albums in {lens}", the rows (R1, R5, R6).
- **Personal Discoveries** (R2, R3), **Add to your collection** (R1, R10), **New releases** (R1, R9): Refresh, the status line, the rows.
- **Artist Deep Dives:** one panel per artist: photo, name, the reason panel labelled "Why this artist" (R7 or R8), then that artist's albums as cards with Get and "…".
- **Phone:** the list switch and lens tabs scroll sideways; each row stacks cover + title, then the reason panel at full width, then the tools.

### 8.2 Library (`library`, `library-albums`)

- The three shelves moved from Home (Recently played, Most played, Newly added), each a row of six covers (four on phones). No reasons: these are your own albums.
- **Browse:** search your library; Show (Artists / Albums); Sort by (Artists: Name, Album count, Date added; Albums: Album name, Artist, Album year, Date added, Track count) with the direction button; Display (list / grid); the thumbnail-size slider (110–320, step 10) only in grid. The sorts and their default directions are today's `LIBRARY_TABS` and `LIBRARY_DEFAULT_ORDER`.
- Artists list: photo (or initials), name, "{n} albums · added {date}". Albums grid: `lr-tiles` with `--tile` set from the slider. "Load more" at the end.

### 8.3 Artist page (`artist`)

- **Hero** (`lr-hero-artistpage`, tinted from the artist photo by the same rule as 4.3): round photo, "Artist", name, genre chips (links to genre pages), "{n} albums in your library · {m} missing", the bio clamped to 4 lines with Read more, More like this and "…". The right column is **Top songs** (5, then "All top songs").
- **In your library:** owned albums as cards with the owned mark (`lr-owned-mark`).
- **Missing albums:** ranked rows without numbers. The reason panel says "You have {n} albums by {artist}. This one is not in your library yet." (R7 wording; `{n}` is the owned count the page already has), with the listeners chip. "All missing albums".
- **Similar artists:** `lr-people` (photo 64, name, "{n} albums in your library" or "Not in your library").

### 8.4 Album page (`album` not owned, Info tab; `album-owned` owned, Reviews tab)

- **Hero** (`lr-hero-page`, tinted from the cover, 4.3): cover, "Album", title, artist with photo, genre (link) · year, then a pill: "Not in your library", or the file quality ("FLAC") when owned.
- **The reason panel at hero size**, labelled "Why this pick · {list}, {lens}", is shown when the page was opened from a discovery list and the album's fields are known; otherwise it is left out. Never on owned albums.
- **Actions:** not owned: Get this album (primary), Save, More like this, "…". Owned: "In your library" (`lr-btn-done`), More like this, "…".
- **Tracklist:** number, title, duration, then a green check ("In your library") or the song's own Get. Below: "{n} songs, {duration} · {k} in your library" and the music-service links (Apple Music, Spotify, Deezer, Qobuz, Bandcamp; only the services the server returns).
- **About** (beside the tracklist on desktop, below on smaller screens): Info / Reviews tabs (`role="tablist"`). Info: the description, Read more, "Description from {source}". Reviews: one card per review (outlet, score, quote, "Read on {outlet}"); the empty and failed notes and "Try again" as today.
- **Similar albums** as cards (owned ones carry the mark and no Get), "All albums"; **Similar artists** as `lr-people`.

### 8.5 Album modal (`album-modal`)

The quick view from any card (`role="dialog"`, `aria-modal`): tinted like the hero, cover with the music-service links under it, then title, artist · year, **the reason panel at hero size**, the short bio, Get this album (primary), Save, More like this, "…", and "Open the album page". Close returns focus to the card. On phones it is a full-height bottom sheet (`lr-sheet` rules).

### 8.6 Genre page (`genre`)

"Genre" eyebrow, the genre name, one line, and **Block this genre**. Artists (`lr-people`), then Albums as cards: owned ones carry the mark, the others Get and "…".

### 8.7 Search (`search`)

The results panel under the top bar (`lr-searchpanel`): the count line, then groups: Artists, Albums and Songs in your library, then **Not in your library** (each row with its own Get). The match is shown in accent and each row has a type pill. Each row's title is a link and its Get is a separate button, so Tab moves through them in order; Escape closes the panel and returns focus to the field. The rows are plain lists, not a `listbox`, because each row holds two controls. With an empty field, focus shows Recent searches, each with a remove button. "/" focuses the field. On phones the panel takes the full width under the field.

### 8.8 Saved (`saved`)

"Albums you bookmarked with Save, newest first. Saving never starts a download." Refresh; a grid of cards with "{artist} · saved {date}", Get, Remove (trash) and "…". The empty note is drawn under the grid. A reason is not shown: L0 checks whether a saved record keeps the list it came from; if it does, a later slice may add the line strip.

### 8.9 Blocklist (`blocklist`)

Three sections as today: Blocked genres (Unblock), Artists hidden with Not this artist (Unblock), More and Less like this (a pill naming the lean, Remove). Each section shows its empty note when it has no rows.

### 8.10 Acquisitions (`acquisitions`)

- The head keeps **Dismiss all successful imports** and Refresh status; the status line counts records and active ones.
- **Rows** (`lr-acq`): cover, title and artist (a song row adds "Song on {album}"), quality profile, a collapsed **Details** disclosure with today's transport lines (peer, source, expected files, transfer states...), then the state, then the actions.
- **State** (`lr-state`): icon + words from `ACQUISITION_STATUS_TABLE`. Tone: active → `text`; caution (`?` statuses such as Needs review) → `text-soft` with the alert icon; error → `danger`; Imported → `ok`; Dismissed → `text-muted`. Colour is never the only signal.
- **Downloading** adds the progress bar, "{n}% complete", speed, total and remaining size, and tracks remaining; the first active row is drawn larger (`lr-acq-big`). "Use next source ({s}s)" appears during a stall, as today.
- **Actions:** Try again on retryable errors, Dismiss, Refresh status. Getting now is not shown in the rail on this page.
- **The line under each state is `details.message` (or `details.error`) as the server sends it.** The sentences in the mockup ("Waiting for the peer to start", "Two candidate folders match…", "Checking tags and moving files…", "No source offered the album…") are stand-in copy. Do not write a sentence per status.

### 8.11 Radio (`radio`)

"Grab the radio" with today's explanation; **App address** (field, help, Save); **Stations**, each with a **Grab** switch (`role="switch"`, "Grabbing" when on); **Heard**, newest first: time, cover, title (link), artist · album · station, then Get (or "Requested"), Save and Remove. Refresh and Clear all sit on the Heard head. A station's second line ("Navidrome station · relayed through this app") is stand-in copy: show only what the station payload carries.

### 8.12 Settings (`settings`, `settings-slskd`, `settings-lastfm`, `settings-listenbrainz`, `settings-discogs`, `settings-appearance`)

- A tab column (Navidrome, slskd, Last.fm, ListenBrainz, Discogs, Appearance; `role="tablist"`, vertical) beside the form; on smaller screens the tabs sit above the form and scroll sideways.
- Forms use `lr-field`: label above, 16px input, help below. **Secrets** are never shown: a saved secret shows the lock line "A key is saved. It is never shown." and the field stays empty.
- Each tab ends with **Save settings** (primary) and **Test connection**; the result is a status line in `ok` or `danger` with an icon and words.
- **Audio quality priority** (slskd): rows with a drag handle, the rank, the label and Move up / Move down (disabled at the ends); the row being dragged is raised. The order is announced in a live region as today.
- **Appearance:** theme choices as radio cards with swatches; Listening Room is the default (D2). The font choice is replaced by a note while Listening Room is on.

### 8.13 Sign in (`login`)

One card on the page background: brand, "Sign in", one line, Username, Password, the error line (`role="alert"`) and Sign in (primary). No shell.

### 8.14 What stays the same

- All API shapes stay as they are. Nothing in this design changes a route's response unless D1 is answered "server".

## 9. Server audit (slice L0)

This slice is needed before any build: it confirms the server data the design depends on and adds what is missing (the owner rule from Bento and Index: plans build the routes they need). It covers:
